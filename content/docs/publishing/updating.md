## Идея

Ваши файлы и ядро лежат отдельно. Вы меняете `content/`, `public/`, `components/`, `theme.css` и `wiki.config.ts`, а `src/` и конфиги сборки приходят из шаблона. Поэтому обновление сводится к одной команде.

## Обновление

:::steps
### Закоммитьте изменения

Команда откажется работать, если в git есть незакоммиченные правки. Так любое обновление можно откатить.

### Обновите ядро

```bash tab="pnpm"
pnpm dlx @opensd/create-wiki@latest upgrade
```

```bash tab="npm"
npx @opensd/create-wiki@latest upgrade
```

Заменяются `src/`, `next.config.ts`, `postcss.config.mjs`, `tsconfig.json`, а в `package.json` обновляются зависимости и скрипты. Ваши поля и дополнительные пакеты остаются.

### Проверьте

```bash
pnpm typecheck
pnpm build
```

Если в новой версии появились поля конфига, `typecheck` покажет, что добавить в `wiki.config.ts`.
:::

## Версии

Версии выходят по [semver](https://semver.org/lang/ru/), что изменилось, описано в [релизах на GitHub](https://github.com/Open-Stream-Deck/Open-Stream-Deck-Wiki/releases).

| Версия            | Что значит                                          |
| ----------------- | --------------------------------------------------- |
| `1.0.0` → `1.0.1` | Исправления, обновляйтесь смело                     |
| `1.0.1` → `1.1.0` | Новые возможности, конфиг совместим                 |
| `1.x` → `2.0.0`   | Ломающие изменения, перед обновлением читайте релиз |

## Если что-то пошло не так

Все изменения видны в `git diff`. Вернуть проект к состоянию до обновления:

```bash
git checkout -- .
git clean -fd src
pnpm install
```
